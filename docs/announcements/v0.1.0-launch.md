# MetricSpec v0.1.0 Launch Draft

MetricSpec is an open source CLI for unit testing business metrics.

The first release focuses on deterministic, fixture-based tests that run locally
and in CI. You write a YAML contract for a metric query, load small CSV/parquet
fixtures into DuckDB, and assert the exact rows the metric should return.
When the answer changes, MetricSpec reports the failing category and field-level
diffs instead of only saying that a query failed.

## Why This Exists

Most analytics tests catch broken pipelines, nulls, or schema drift. They do not
usually prove that a business metric still means the same thing after a query
change. MetricSpec treats important metrics like application behavior: define
the expected examples, run them in CI, and review explainable failures.

## Try It

Before package publication, from a checkout:

```bash
uv sync --extra dev
uv run metricspec init demo
cd metricspec-demo
uv run --project .. metricspec run
```

After publication:

```bash
uvx metricspec init demo
cd metricspec-demo
uvx metricspec run
```

## What Is Included

- Contract YAML schema for metric tests.
- DuckDB fixture runner.
- Read-only SQL safety guard.
- SQL-shape checks.
- Numeric tolerance and field-level diffs.
- Human, JSON, and JUnit output for CI.
- Demo ecommerce metric with passing and failing contracts.

## What Comes Next

The next focus areas are dbt/MetricFlow integration, richer SQL-shape analysis,
and a GitHub Actions summary experience.

Feedback wanted: metric-testing workflows, contract schema ergonomics, and
adapter priorities.
